# 정원 대시보드 / 내보내기

## 사용

각 정원 HUD의 **대시보드 생성하기**를 누르면 그 순간 정원에 적용된 시세(기존 live overlay 포함)를 복사합니다. 정원을 여는 것만으로 대시보드 계산·공시/뉴스 조회·파일 생성은 시작하지 않습니다. 기존 정원의 시세 폴링은 그대로 유지합니다.

- 대시보드1: 총평가액, 평가손익, 매수원금 대비 수익률, 원금, 정규 종목 섹터별 구성·비중·수익률, 종목 상위30/하위30. 60종목 이하는 중복 없이 전체 순위, 미확인 수익률은 제외.
- 섹터 **분석**: 대시보드2의 종목 평가액 비중, 매수원금 대비 수익률, 종목별 공시·뉴스. UI는 30종목/페이지, 공시·뉴스는 10종목/페이지이며 MD는 모든 페이지를 포함하고 PDF/PPTX/PNG는 가로 한 장 요약입니다.
- **시세 새로고침 · 재생성**: 해당 정원에 심긴 티커만 기존 `/api/quotes`로 조회(20개/배치, 최대 3배치 동시), 기존 값은 실패 시 유지하고 성공 건수를 표시합니다. 새로운 스냅샷은 정원 전체 화면으로 돌아갑니다.
- **다시 분석**: 선택 섹터의 공시/뉴스를 재조회. 뉴스 응답은 5분 HTTP 캐시가 적용될 수 있습니다.
- PDF/PPTX/PNG/MD 다운로드 후 **생성 파일 공유**를 누릅니다. 네이티브 파일 공유 지원 시 실제 파일을 공유하고, 미지원/실패 시 다운로드합니다. 사용자 취소는 재다운로드하지 않습니다. URL은 공유하지 않습니다. 파일에 보유 금액이 포함됨을 UI에서 안내합니다.
- 닫기/Escape는 포커스를 생성 버튼으로 돌리고 생성 대기 결과를 취소합니다. localStorage, 생성 정원 시드/숨김/삭제 로직은 변경하지 않습니다.

## 계산 / 결측

현재 평가액 = 보유수량 × 적용 현재가. 손익 = 평가액 − 보유수량 × 실제 매수가. 수익률 = 손익 / 매수원금. 배당, 세금, 수수료 제외. 중복 티커는 비용을 합산합니다. 대표업종은 `representativeIndustries`의 별도 KIND 분류 스냅샷을 사용하고 분류가 없으면 **미분류·검토 필요**로 표시합니다. 기존 quote/투자테마와 별개입니다. `Position.sector`의 임의 정원명으로 대체하지 않습니다.

가격 0/음수/NaN/Infinity는 미확인으로 처리하며 0원/−100%로 만들지 않습니다. 미확인 종목이 있으면 해당 합계·손익·비중은 `—`입니다. 원금 0은 수익률 `—`, 빈 정원 합계는 0.00억원. 모든 금액은 **억원 소수점 둘째 자리**(반올림이므로 표시된 작은 금액의 합과 총액은 다를 수 있음).

생성 시각은 거래 시각이 아닙니다. 기존 quote 객체/API가 개별 가격 시각·공급자를 보존하지 않으므로 이를 만들어내지 않고 미제공으로 안내합니다. 기본 스냅샷과 KIS→Yahoo→pykrx→Naver 기존 체인을 사용합니다.

## 실제 로컬 DB와 안전한 게시

발견·읽기 전용으로 확인한 DB:

- `~/wiki/10-Projects/trading-analysis/data/dart_signals.db`, `filings`: 4,562행, DB 최신 접수일 **2026-05-22**.
- `~/wiki/10-Projects/sector-monitor/data/sector_monitor.db`, `events`: 66행, DB 최신 접수일 **2026-05-14**.
- `kr-market-brain` 자체에서 발견한 SQLite는 MA 교차 이벤트 DB이므로 공시 DB로 사용하지 않았습니다.

빌더는 **공개 종목코드/보고서명/접수번호만** SELECT하여 `src/data/dashboard-disclosures.v1.json`을 생성합니다. 6자리 종목코드/14자리 접수번호/날짜 검증, 제목 키워드 중요공시 필터, 중복 제거 후 종목별 최신 5건입니다. 최초 게시 스냅샷은 282건입니다. RAW XML, DB 전체, 투자 메모, 시그널 점수, 인증정보, 절대 홈 경로는 게시하지 않습니다.

```sh
python3 scripts/build-dashboard-disclosures.py --wiki "$HOME/wiki"
python3 -m unittest discover -s scripts -p test_build_dashboard_disclosures.py
```

DB가 없거나 유효한 공시가 0건이면 기존 스냅샷을 빈 파일로 덮어쓰지 않습니다. **Vercel은 로컬 디스크를 읽지 않습니다.** DB를 갱신한 다음 이 빌더를 수동 실행하고 공개 JSON을 검토·게시해야 반영됩니다. 게시 배포는 GitHub main → 기존 Vercel 프로젝트 연동을 사용하며, 정확한 커밋의 Vercel 성공 상태와 운영 URL을 별도로 검증합니다.

현재 DB의 5월 자료를 10월의 최신 공시로 가장하지 않습니다. UI는 DB 최신일, 스냅샷 생성일, 90일 초과 **과거 공시**, 미수집/조회실패를 표시합니다. 최신/전 시장 공시 완전성은 보장하지 않습니다. `최대주주` 등 제목 키워드에 따른 중요도이지 전문가 평가가 아닙니다.

`GET /api/dashboard-research?tickers=005930,000660`는 게시 공시를 먼저 읽고 Naver 종목 뉴스 API의 최신 제목 최대3개/종목을 결합합니다. 1~20개 대문자 영숫자 티커만 허용, 서버 최대3개 뉴스 요청 동시, 8초 타임아웃, 본문 미게시, HTTPS Naver 원문 링크 허용 목록. 클라이언트는 **선택 섹터의 심긴 종목만** 순차 배치 요청합니다. 뉴스 중요도·정확성은 별도 검증하지 않으며 출처·발행일·조회일을 표시합니다.

## 내보내기

- `dashboard-report.ts`: 화면 페이지 수와 무관한 전체 보고서 데이터, MD, 표/순위/출처.
- `dashboard-export.ts`: 동일한 고정 16:9 scene에서 **PDF 정확히 1페이지, PPTX 정확히 1슬라이드, PNG 3840×2160**를 만듭니다. 화면의 정원 테마와 별도로 내보내기는 흰색/연회색 바탕, 짙은 남색 제목, 조용한 테두리, 작은 모서리, 그림자·장식 아이콘 없는 재무 보고서 스타일입니다.
- 상단은 제목·정원명·스냅샷 생성 시각과 총평가액/매수원금/평가손익/총수익률 4개 동일 크기 지표입니다. 현 데이터 모델은 주식만 수집하므로 **정원 내 주식 기준 · 비주식 자산 미입력**을 명시합니다. 사진의 수치/분류나 현금 0원을 만들어 넣지 않습니다.
- 중단은 24/38/38 비율의 섹터 목록/평가액 비중/매수원금 대비 성과입니다. 정규 섹터를 사용하며 최대8행, 초과 건수와 MD 전체 안내를 명시합니다. 비중과 수익률은 각각 공통 선형 축이며 성과는 0 기준선과 양수 녹색/음수 적색을 사용합니다.
- 하단은 상위30/하위30을 각각 10행×3열로 배치합니다. 60종목 미만은 중복 없이 전체를 두 그룹으로 나누고 실제 표시 개수를 제목에 표시합니다. 하위는 가장 낮은 수익률부터 오름차순이며 양수 하위도 녹색입니다. 종목명은 축약하지 않고 줄바꿈합니다. 순위에 손익도 억원으로 표시합니다.
- 선택 섹터(대시보드2)는 동일한 스타일의 평가액 순 종목 목록/섹터 내 비중/매수원금 대비 수익률 차트와 하단 공시·뉴스 링크6건을 제공합니다. 상단 4지표는 선택 섹터만 집계하며 부모 정원명·정원 내 비중을 별도로 표시합니다. 수익률 차트에도 평가액(억원)을 표시합니다. 모든 종목의 공시를 뉴스보다 먼저 배치하며 유형 안에서는 보고서 순(중요도 순 아님)입니다. 중단 최대8종목, 하단 최대6링크는 표시/전체 건수를 명시하고 MD에는 선택 종목 전체의 수량·원금·평가액·비중·수익률·손익 및 모든 공시/뉴스/분류 근거를 담습니다. 미조회/실패 건수, 게시 스냅샷 생성일·뉴스 조회일·DB 최신 공시일·완전성 한계를 유지합니다. 긴 뉴스 제목만 …로 축약하며 MD는 전체입니다.
- PDF와 PNG는 OFL **Noto Sans KR Regular** 글꼴을 사용합니다. PPTX는 편집 가능한 텍스트에 Noto Sans KR 지정(파일은 내장하지 않으므로 해당 글꼴 설치 필요). 화면 Gaegu/정원 테마는 그대로입니다. PDF는 26⅔×15인치의 16:9 보고서 캔버스로 종목명 18pt(전체 순위 16pt), 지표 28pt, 안내 15pt, 보조 금액 13pt입니다. 종이 인쇄 시 축소될 수 있습니다.
- `public/fonts/NotoSansKR-Regular.ttf`는 Google Fonts `ofl/notosanskr/NotoSansKR[wght].ttf`에서 fontTools로 만든 정적 글꼴입니다. `OFL-NotoSansKR.txt` 동봉. PNG는 같은 scene을 Canvas로 그리며 이미지 특성상 링크는 클릭할 수 없습니다. PDF/PPTX와 MD 링크는 유지합니다.
- 공유는 실제 파일 생성 후 별도의 클릭으로 실행하여 브라우저 user activation을 유지합니다.

## 재현 가능한 검증

```sh
npm test
npm run build
npm run start -- --port 3107
# 다른 터미널: 다운로드·뷰포트·실제 뉴스 API·refresh·공유 폴백 검사
DASHBOARD_ARTIFACT_DIR=/absolute/evidence/path node scripts/verify-dashboard-browser.mjs
# 합성 65종목 전체 내보내기 (fixture임을 명시)
DASHBOARD_ARTIFACT_DIR=/absolute/evidence/path npm test -- src/lib/dashboard-export.test.ts
# pip: pymupdf, python-pptx 필요
python scripts/verify-dashboard-exports.py /absolute/evidence/path
```

브라우저 검증은 독립 Chromium context라 사용자의 기존 localStorage를 변경하지 않습니다. native share는 API payload mock으로 확인하고 다운로드 폴백은 실제 파일로 확인합니다. 모바일 390×844, 데스크톱1440×1000의 `scrollWidth===clientWidth`, JS pageerror 없음, 대시보드 생성 전 공시/뉴스 요청0건을 검사합니다. PDF/PPTX는 정확히 한 장, 요약 텍스트·도형 경계와 링크 구조를 확인하되, LibreOffice/PowerPoint 실제 시각 렌더링은 별도 환경에서 확인해야 합니다.

기존 저장소 전체 lint에는 `.vercel/output` 생성물 및 기존 garden-context/garden-scene/garden-view 오류가 있습니다. 대시보드 신규 소스 대상 eslint는 통과합니다. 기존 Next/Vitest 등 npm audit 취약점은 범위 밖으로 남겼고, 새 PPTX 의존성의 image-size는 안전한 2.0.4로 override했습니다.
